# 1. 주제와 요구사항

## 정한 주제

**TripMate: 취향·성향 기반 다인원 여행 역할 배정과 숙소 투표**

7~8명이 가는 여행에서 생기는 두 가지 피로를 줄인다.

| 문제 | TripMate 가 하는 일 |
|---|---|
| 누가 운전·총무·장보기를 맡을지 눈치 싸움 | 설문(차 유무, 계획 성향, 맡기 싫은 일, 이동 제약)으로 **역할을 추천**하고, 보드에서 같이 바꾼다 |
| 숙소 투표가 다수결이라 싫어하는 사람이 생김 | 조건별 **평균과 최솟값**을 같이 보여 주고, 숙소마다 그룹 취향 점수를 매겨 투표한다 |

"그냥 카톡 투표 쓰면 되지 않나?"에 대한 답: 카톡 투표는 표만 센다. TripMate 는 **왜 그 사람에게 그 역할인지 근거**와 **의견이 갈린 조건**을 보여 준다.

## 기능 3개 (= 3명)

| 기능 | 담당 | 표 |
|---|---|---|
| 로그인·초대·여행방 | 박재현 | app_user, trip, member |
| 설문·역할 추천·실시간 역할 보드 | 문지훈 | survey_answer, role, assignment |
| 숙소 링크·투표·그룹 취향 | 김현수 | stay, vote |

## 요구사항

번호 하나가 기능 하나다. 코드와 PR 에서 이 번호를 쓴다(예: `REQ-07`). ✅ 는 이미 동작하는 것, 빈칸은 남은 일.

| 번호 | 요구사항 | 담당 | 화면 | 끝남 |
|---|---|---|---|---|
| REQ-01 | 카카오로 로그인·로그아웃할 수 있다 | 박재현 | SCR-02 | ✅ |
| REQ-02 | 여행방을 만들 수 있고, 만든 사람이 방장이 된다 | 박재현 | SCR-03 | ✅ |
| REQ-03 | 초대 링크로 방에 참여할 수 있다 | 박재현 | SCR-04, SCR-05 | ✅ |

| REQ-05 | 방장은 방 정보를 고치고 방을 지울 수 있다 | 박재현 | SCR-05 | |

| REQ-10 | 참여자는 역할 카드를 옮길 수 있고, 동시에 옮기면 늦은 쪽이 막힌다 | 문지훈 | SCR-07 | ✅ |

| REQ-16 | 숙소를 올린 사람은 조건을 고치고 숙소를 지울 수 있다 | 김현수 | SCR-08 | |

규칙:
- REQ-08: "이동이 불편한 사정"은 다른 사람에게 이유 없이 "이동 적은 역할 우선"으로만 보인다
- REQ-09: 추천은 모두의 배정을 갈아엎으므로 방장만
- REQ-18: 출발 동네는 본인과 방장만 보고, 다른 사람에게는 거리·시간만 보인다. 카카오 키가 없으면 안내만 나온다
- REQ-13: 서버가 사용자가 준 주소로 접속하므로 내부망 주소는 막는다
