# 5. 역할 분담

**기능 하나를 한 사람이 화면부터 DB 까지 맡는다.** 화면 담당, DB 담당처럼 가로로 나누지 않는다.
그래야 발표 때 각자 자기 기능의 흐름(브라우저 → Controller → Service → Repository → DB → 화면)을 끝까지 설명할 수 있다.

## 사람과 기능

| | 팀원 A (팀장) | 팀원 B | 팀원 C |
|---|---|---|---|
| GitHub | Parkjaehyun1204 | jihun-moon | khs219012 |
| 이름 | 박재현 | 문지훈 | 김현수 |
| 맡은 기능 | 회원가입·로그인 + (기능 1) | 기능 2 | 기능 3 |
| 맡은 요구사항 | REQ-01, REQ-02, | | |
| 맡은 화면 | SCR-01~03, | | |
| 맡은 표 | members, | | |
| 같이 하는 일 | 공통 레이아웃(header), 프로젝트 뼈대, PR 합치기 | ERD 합치기, `schema.sql` | 발표 자료 합치기, 시연 순서 |
| 발표 시간 | 분 | 분 | 분 |

기능 이름이 정해지면 위 칸을 채운다. 기능 크기가 비슷하도록 나눈다.

## 일정 (4주 기준, 마일스톤과 같다)

| 주 | 할 일 | 끝났다는 기준 |
|---|---|---|
| 1주 | 주제, 요구사항, 화면 목록 | `01`, `02` 문서 채움 |
| 2주 | ERD, URL, 프로젝트 뼈대 | `03`, `04` 문서, `schema.sql`, 서버가 뜬다 |
| 3주 | 기능 구현 (각자 CRUD) | 자기 기능의 등록·목록·상세·수정·삭제가 된다 |
| 4주 | 검증, 합치기, 발표 준비 | `docs/parts/<아이디>.md` 채움, 리허설 1번 |

## 발표 순서 (예시)

1. 팀장: 주제와 이유, 요구사항, ERD, 전체 구조 (2분)
2. 각자: 자기 기능 시연 + 요청 흐름 하나 설명 + 어려웠던 점 (각 3분)
3. 팀장: 정리, 질문 받기

각자 준비는 `docs/parts/_틀.md` 를 복사해서 `docs/parts/<GitHub아이디>.md` 로 만든다.
