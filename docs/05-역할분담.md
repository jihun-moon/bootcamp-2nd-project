# 5. 역할 분담과 일정

**기능 하나를 한 사람이 화면부터 DB 까지 맡는다.** 화면 담당, DB 담당처럼 가로로 나누지 않는다.
그래야 발표 때 각자 자기 기능의 흐름(화면 컨트롤러 → 템플릿의 jQuery → API Controller → Service → Repository → DB → 화면)을 끝까지 설명할 수 있다.

## 지금 상태

MVP 핵심(설문 → 역할 추천 → 실시간 보드 → 숙소 투표 → 로그인·초대)은 **한 사람이 먼저 만들어 두었다**. 각자 맡은 기능의 코드를 **읽고, 설명할 수 있게 다듬고, 남은 요구사항을 채우는 것**이 이번 일이다. 테스트 56개가 있으니 고친 뒤 `./gradlew test` 가 그대로 통과해야 한다.

화면은 수업대로 Thymeleaf + jQuery 로 바꿨다(Next.js 를 걷어냄). 문지훈 몫의 Service 분리(`SurveyService`, `RoleService`)는 그때 같이 했다.

## 모두 처음 할 일 (1주 차)

1. 저장소를 받아 [README 의 로컬 실행](../README.md#로컬-실행)대로 띄우고, 개발용 로그인으로 예시 방을 끝까지 눌러 본다
2. 자기 기능의 요청 하나를 골라 브라우저 → 화면 파일 → Controller → Repository → DB 까지 코드로 따라가 본다
3. **Controller 에 있는 계산을 Service 로 옮긴다** — [팀 코드 규칙](코드-규칙.md)의 "한 층은 한 가지 일". 박재현(`TripController`)·김현수(`StayController`) 몫이 남았다. 본보기는 `SurveyService`·`RoleService`. 테스트가 그대로 통과하면 된다
4. `docs/parts/_틀.md` 를 복사해 `docs/parts/<GitHub아이디>.md` 를 만든다

## 발표 순서 (예시)

1. 팀장: 주제와 이유, 요구사항, ERD, 전체 구조(화면 컨트롤러 + jQuery → API, 세션 쿠키) (2분)
2. 각자: 자기 기능 시연 + 요청 흐름 하나 설명 + 어려웠던 점 (각 3분)
   - 박재현: 초대 링크 → 로그인 → 참여, 남의 방은 404 인 이유
   - 문지훈: 설문 → 헝가리안 추천 → 두 화면에서 동시에 카드 옮기기(409)
   - 김현수: 링크 올리기(미리보기, 내부 주소 차단) → 투표 → 갈린 조건
3. 팀장: 정리, 질문 받기
