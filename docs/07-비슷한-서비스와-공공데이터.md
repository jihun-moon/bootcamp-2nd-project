# 7. 비슷한 서비스와 공공데이터 활용안

2026-11-20 조사했다. 앱 기능은 대부분 앱스토어 소개 글로 확인했고 직접 설치해 보지는 않았다.
API 세부 칸 이름 중 공식 문서로 확인하지 못한 것은 표에 "확인 필요"로 남겼다.

이 문서는 제안이다. 고칠 곳이 남의 기능이면 [역할 분담](05-역할분담.md)대로 그 사람과 먼저 맞춘다.

## 1. 비슷한 서비스

| 갈래 | 서비스 | 하는 일 | 우리와 다른 점 |
|---|---|---|---|
| 숙소·여행지 투표 | Troovy(트루비) | 초대 코드로 한 방, 익명 투표, 숙소·항공 비교 투표, 정산 | 가장 비슷하다. 다수결이고 역할 배정은 없다 |
| | Troupe | 날짜·여행지·숙소 투표 | 초대 링크가 안 된다는 후기, 1년째 업데이트 없음 |
| | Kayak Trip Huddle | 하트 1~3개로 점수 | 평균만 본다. 2018년 기능이라 지금도 되는지 모른다 |
| | Travote, TripSquad, 저니피키 | 후보에 투표 | 표 수만 센다 |
| | Grotu | 설문을 보내 차트로 보여 줌 | 설문 + 차트라 방식이 닮았다 |
| 할 일·권한 | Travita | 사람에게 할 일·마감일을 맡김 | 사람이 직접 고른다 |
| | TripLoom, TripCrew | 방장·편집·보기 권한 | 여행 역할이 아니라 권한이다 |
| | Trip Pilot, HousMthr | 준비물·장보기 목록, 방 배정 | 목록만 있다 |
| 일정·정산 | 트리플, 트리브, Wanderlog, 트랩플랜 | 같이 일정 짜기, 가계부, 예약 | 여행 내내 여는 앱이다. 우리는 없다 |
| 성향 테스트 | 모두의여행(MOYO), 트래블어스 | 성향 테스트로 모르는 사람과 동행 매칭 | 테스트를 매칭에 쓴다. 역할 추천은 없다 |

찾은 범위 안에서 **설문으로 여행 안의 역할을 추천하고 근거를 보여 주는 곳은 없었다.**
숙소 투표에서 조건별 최솟값으로 "의견 갈림"을 보여 주는 곳도 없었다. 이 두 가지가 우리 무기다.

## 2. 지금 그대로면 안 쓰일 이유

코드와 설계 문서를 읽고 적었다.

| 문제 | 어디서 보이나 |
|---|---|
| 8명이 다 설문해야 값이 나온다. 2~3명이 안 들어오면 멈춘다 | SCR-05 설문 진행 3/8 |
| 한 번 정하면 다시 열 이유가 없다 | 일정·준비·여행 중 화면이 없다 |
| 숙소 조건을 올린 사람이 손으로 체크한다. 틀리면 점수가 틀어진다 | `LinkPreview` 는 `og:title`, `og:image` 두 개만 읽는다 |
| 가격이 없다 | `src/main`, `docs` 에 price·가격·예산이 한 번도 안 나온다 |
| 역할 추천의 근거가 설문 답뿐이다. "차 있음 +4" 는 단톡방 한마디와 다를 게 없다 | `RoleScorer` |
| 초대받은 사람은 링크 → 카카오 로그인 → 설문 6장을 거친다 | SCR-04 → SCR-02 → SCR-06 |

일정·정산·예약까지 만들면 트리플과 정면으로 붙는다. 그 싸움은 안 한다.
**"8명 여행에서 정하기 싫은 두 가지를 근거 있게 빨리 끝내는 도구"** 로 좁히고,
근거를 설문 말고 **바깥 데이터** 로 늘리는 쪽으로 간다.

## 3. 지금 가진 키

| 키 | 있나 | 쓰는 곳 |
|---|---|---|
| 카카오 REST API 키 | 있다(`KAKAO_CLIENT_ID`) | 로그인. 같은 앱에서 카카오 로컬 API 를 켜면 같은 키로 부른다 |
| 공공데이터포털 서비스키 | 없다 | 아래 3~6번 API 에 하나로 쓴다. 가입 후 API 마다 활용 신청 |
| 오피넷 키 | 없다 | 유가. 오피넷에서 따로 받는다 |

새 키는 지금처럼 `secrets.properties` 에 넣고 git 에 올리지 않는다. 예: `DATA_GO_KR_KEY=...`, `OPINET_KEY=...`

## 4. 쓸 만한 API

| 번호 | API | 주는 것 | 한도·조건 |
|---|---|---|---|
| API-1 | 카카오 로컬 (주소 검색, 키워드·카테고리 검색) | 주소 → 좌표, 숙소 주변 대형마트(`MT1`)·편의점(`CS2`)과 거리 | 헤더 `Authorization: KakaoAK {REST키}`. 2026-07-21 부터 카카오맵 계열은 계정의 첫 앱만 무료 쿼터 |
| API-2 | 카카오모빌리티 자동차 길찾기 | 출발 → 숙소 거리·시간, 통행료(확인 필요) | 무료 쿼터 안이면 제휴 없이 쓴다고 담당자가 답했다. 수치는 콘솔에서 확인 |
| API-3 | 한국관광공사 TourAPI 국문 관광정보(숙박) | 숙소 이름·주소·좌표, 바베큐·주차·객실 수 같은 소개 칸(칸 이름 확인 필요) | 공공데이터포털, 무료 |
| API-4 | 한국관광공사 반려동물 동반여행 | 반려동물 받는 숙소와 조건 | 무료, 개발계정 일 1,000건 |
| API-5 | 한국관광공사 열린관광지·무장애 정보 | 휠체어·유아차로 다닐 수 있는 곳 | 무료. 숙소 단위 칸이 있는지 확인 필요 |
| API-6 | 행정안전부 인허가: 숙박업, 농어촌민박업 | 사업장명, 주소, 허가일, **영업상태** | 무료, 일간 갱신, 개발계정 일 10,000건 |
| API-7 | 기상청 단기예보 `VilageFcstInfoService_2.0/getVilageFcst` | 3일 안쪽 시간별 날씨(격자 `nx`, `ny`) | 무료. 3일 넘는 날씨는 중기예보 API 를 따로 확인 |
| API-8 | 오피넷 시도별 평균 유가 `avgSidoPrice.do` | 휘발유·경유·LPG 평균가 | 오피넷 키 필요 |

**숙소 가격은 공공데이터에 없다.** 야놀자·에어비앤비 같은 예약 사이트 가격을 긁는 건 약관에 걸린다.
가격은 링크 올린 사람이 손으로 넣는다.

## 5. 기능마다 붙일 자리

### 숙소 (김현수)

| 제안 | 쓰는 API | 화면에 보이는 것 |
|---|---|---|
| 1박 총액 칸과 설문 "1인 예산 상한" | 없음 | 숙소 표에 "1인 6.2만 원 · 예산 넘는 사람 2명". 최솟값 방식과 그대로 이어진다 |
| 조건 자동 채움 | API-3 | 링크 제목으로 TourAPI 숙박을 찾아 바베큐·객실 수 등을 미리 체크해 둔다. 사람은 고치기만 한다 |
| 신고된 숙소 표시 | API-6 | 이름·주소가 맞는 인허가 기록이 "영업" 이면 "신고 숙소", 폐업이면 경고 |
| 다른 사람도 조건 정정 | 없음 | "온수풀 없어요" 표시. 올린 사람만 고치는 REQ-16 과 같이 본다 |
| 반려동물 | API-4 | 설문에 "반려동물 동반" 이 있으면 받는 숙소만 점수를 준다 |

신고 숙소 표시가 차별점으로 가장 크다. 단톡방에서 링크만 돌리면 미신고 숙소를 알 방법이 없다.
다만 이름·주소로 맞추는 거라 틀리게 붙을 수 있다. 맞는 게 없으면 "확인 못 함" 으로만 둔다.

### 역할 (문지훈)

| 제안 | 쓰는 API | 바뀌는 것 |
|---|---|---|
| 운전 정원 자동 | API-1, API-2 | 숙소까지 편도가 2시간을 넘으면 운전 정원을 1 → 2 로 추천하고 근거에 "편도 2시간 40분" |
| 출발지별 운전 점수 | API-1, API-2 | 설문에 출발 동네를 묻는다. 차 있는 사람끼리 숙소에 더 가까운 쪽이 아니라, 다른 사람을 태우러 가기 좋은 쪽에 점수 |
| 장보기 거리 | API-1 | 숙소 반경 5km 안 대형마트가 없으면 장보기 역할에 "차 필요" 를 붙이고 차 없는 사람은 감점 |
| 총무 회비 근거 | API-2, API-8 | 총무 카드에 "기름값 약 4.1만 + 통행료 1.2만 + 숙소 49.6만 = 1인 6.9만" |

출발지는 이동 제약처럼 민감할 수 있다. 동네(구 단위)까지만 받고 다른 사람에게는 "출발 가까움" 으로만 보인다.

### 방 (박재현)

| 제안 | 쓰는 API | 화면에 보이는 것 |
|---|---|---|
| 방 지역을 주소 검색으로 고르기 | API-1 | 좌표가 생겨야 날씨·길찾기·마트가 돈다. 다른 제안이 다 이걸 쓴다 |
| 출발 날씨 | API-7 | 출발 3일 전부터 개요에 날씨. 비 오면 "바베큐 우천 대비" 를 바베큐 역할 할 일에 붙인다 |
| 설문 안 한 사람 다시 부르기 | 없음 | 안 한 사람 이름이 들어간 카톡용 글 복사 |
| 결과 카톡용 복사 | 없음 | `운전: 재현, 도윤 / 총무: 민지 / 숙소: 숲속 독채 (5표, 다 OK)` |

## 6. 앱 설치 없이, 휴대폰·PC 어디서나

### 다른 서비스는 어떻게 들어오나

| 서비스 | 들어오는 길 | 초대받은 사람이 할 일 |
|---|---|---|
| Troovy, Troupe, Travote, TripSquad, 저니피키 | 앱스토어 앱 | 앱 설치 → 가입 → 초대 코드 |
| 트리플, 트리브 | 앱이 중심 | 앱 설치 → 가입 |
| Wanderlog | 앱 + PC 웹 | 링크나 이메일로 초대, 가입 |
| 카카오톡 투표(게시판 다중 투표) | 단톡방 안 | 누르면 끝. 장소·날짜·메뉴를 한 게시판에 3건까지 |

찾아본 그룹 여행 앱은 거의 다 **앱을 깔아야 들어온다.** 8명 중 한 명이라도 "앱 깔기 귀찮아" 하면 그 방은 멈춘다.
진짜 경쟁자는 카톡 투표다. 설치가 없고 이미 단톡방 안에 있다.
다만 카톡 투표는 표만 세고, 결과를 바깥으로 꺼내는 API 가 없다고 카카오가 답했다. 결과를 사람이 옮겨 적는다.

TripMate 는 처음부터 웹이라 **링크 하나로 휴대폰 브라우저에서 바로 열린다.** 이게 앱 서비스들보다 앞서는 가장 큰 점이다.
카톡 안에서 링크를 누르면 카톡 내장 브라우저로 열리니, 사용자 입장에서는 카톡을 떠나지 않는다.

### 지금 휴대폰에서 걸리는 것

`style.css`, `templates/`, `roles.js` 를 읽고 적었다. 실제 휴대폰으로는 아직 안 열어 봤다.

| 무엇 | 지금 | 문제 | 고칠 방향 | 담당 |
|---|---|---|---|---|
| 화면 폭 | `viewport` 있음, `.page` 최대 960px, 카드·보드가 `auto-fill` 그리드 | 기본은 된다. `@media` 는 다크 모드 하나뿐 | 아래 표·보드만 손본다 | 각자 |
| 역할 카드 옮기기 | `draggable` + `dragstart`/`drop` (HTML5 끌어 놓기) | 휴대폰 브라우저, 특히 카톡 내장 브라우저에서는 손가락으로 끌기가 잘 안 될 수 있다(확인 필요) | 카드를 누르면 역할 목록이 떠서 고르는 방식을 같이 둔다. 끌기는 PC 용으로 남긴다 | 문지훈 |
| 숙소 표 | 숙소 × 조건 열이 가로로 늘어나는 표 | 휴대폰 폭(360px)에서 조건이 7개면 넘친다 | 좁은 화면에서는 숙소마다 카드 한 장(점수·표·조건 배지) | 김현수 |
| 설문 | 한 장에 한 질문 | 휴대폰에 이미 맞다. 단추를 엄지로 누르기 좋게 크게만 | 단추 높이 44px 이상 | 문지훈 |
| 초대 링크 미리보기 | `og:` 메타 태그가 하나도 없다 | 카톡에 `/join/abcd` 를 보내면 제목·사진 없이 주소만 보인다. 누를 마음이 안 든다 | `join.html` 에 `og:title`("재현님이 '겨울 펜션 2박 3일'에 초대했어요"), `og:description`("설문 1분이면 역할과 숙소를 같이 정해요"), `og:image` | 박재현 |
| 홈 화면에 추가 | 없음 | 여행 직전에 다시 찾기 어렵다 | `manifest.json` 과 아이콘만 두면 휴대폰 홈 화면에 앱처럼 붙는다. 정적 파일이라 스택이 늘지 않는다 | 박재현 |

### 들어오게 만드는 흐름

사람이 들어오는 길은 단톡방 하나다. 방장 한 명만 TripMate 를 알면 된다.

```
방장: 방 만들기 → 초대 링크 복사 → 단톡방에 붙임
   ↓ (카톡 미리보기: "재현님이 초대했어요 · 설문 1분")
친구: 누름 → 카톡 안에서 열림 → 카카오 로그인 한 번(카톡 안이라 거의 바로) → 설문
   ↓
방장: "아직 안 한 사람: 시우, 하은" 글 복사 → 단톡방에 다시
   ↓
결과: "운전 재현·도윤 / 총무 민지 / 숙소 숲속 독채(5표, 다 OK)" 글 복사 → 단톡방에
   ↓
다음 여행 때 방장이 또 만든다. 이번에 초대받은 7명이 다음 방장 후보다
```

카톡과 싸우지 않고 **카톡 단톡방에 붙여 쓰는 도구** 로 간다. 결과를 카톡에 돌려보내면 그 글 자체가 광고가 된다.
결과 글 끝에 `TripMate 로 정했어요 · 링크` 한 줄을 붙인다.

### 문턱을 더 낮추려면

| 제안 | 효과 | 걸리는 것 |
|---|---|---|
| 설문을 꼭 필요한 3개(차, 맡기 싫은 일, 숙소 조건)로 줄이고 나머지는 나중에 | 1분 안에 끝난다 | 추천 정확도가 조금 준다 |
| 초대 링크로 들어오면 로그인 전에 방 이름·참여자·설문 질문을 먼저 보여 준다 | 뭘 하는 곳인지 보고 로그인한다 | REQ-04(참여자만 본다)와 부딪힌다. 방 이름·인원만 보이게 선을 정한다 |
| 결과 화면을 로그인 없이 보는 읽기 전용 링크 | 설문 안 한 사람도 결과는 본다 | 이동 제약 같은 민감한 근거는 빼고 보여 준다 |

## 7. 우리가 모으는 강점

다른 서비스에서 좋은 것과 우리 무기만 모으면 이렇게 된다.

| 강점 | 어디서 왔나 | TripMate 에서 |
|---|---|---|
| 설치 없음 | 카톡 투표 | 링크 하나, 카톡 안에서 열림 |
| 한 방에 다 같이 | Troovy, Troupe | 초대 링크 방, 실시간 반영(SSE) |
| 표가 아니라 불만을 본다 | 우리만 | 조건별 평균 + 최솟값, "의견 갈림" |
| 근거 있는 역할 | 우리만 | 설문 + 길찾기·유가로 "왜 이 사람이 운전인지" |
| 믿을 수 있는 숙소 | 우리만(공공데이터) | 신고 숙소 표시, 조건 자동 채움 |
| 돈 얘기 | 트리플·트리브 가계부 | 정산까지는 안 하고, 1인 예상 금액만 보여 준다 |
| 결과가 다시 퍼진다 | 우리 흐름 | 카톡용 결과 글 |

## 8. 만들 때 지킬 것

- 바깥 API 는 **있으면 좋은 것** 이다. `LinkPreview` 처럼 실패하면 빈 값을 주고 화면은 그대로 뜬다. 키가 없어도 서버가 떠야 한다
- 부르는 코드는 `component/` 에 `XxxClient` 하나로 둔다(예: `component/TourApiClient`, 지금 있는 `KakaoMapClient`·`FuelPriceClient` 와 같은 자리). 수업의 RestTemplate 실습 꼴 그대로다. `spring-boot-starter-webmvc` 에 이미 들어 있어서 라이브러리를 더하지 않는다
- 같은 숙소·같은 날을 여러 번 부르지 않게 결과를 DB 칸에 저장한다. 개발계정 한도가 일 1,000건인 API 가 있다
- 테스트에서는 바깥으로 안 나가게 `XxxClient` 를 가짜로 바꾼다. `./gradlew test` 가 인터넷 없이 통과해야 한다
- 사용자가 준 주소로 서버가 직접 나가는 건 `LinkPreview` 하나뿐이다. 새 API 는 우리가 정한 주소만 부른다
- 공공데이터를 쓰면 화면 아래에 출처를 적는다(한국관광공사, 행정안전부, 기상청, 오피넷)

## 9. 순서

| 순서 | 할 일 | 담당 | 왜 먼저 |
|---|---|---|---|
| 1 | 초대 링크 `og:` 미리보기, 카톡용 결과·재촉 글 복사 | 박재현 | API 없이 하루면 되고, 사람이 들어오는 길이 여기 하나다 |
| 2 | 휴대폰에서 역할 카드 누르고 고르기, 숙소 표를 카드로 | 문지훈, 김현수 | 들어온 사람이 휴대폰에서 막히면 끝이다 |
| 3 | 숙소 가격·예산 칸 | 김현수 | API 없이 되고, 지금 가장 큰 구멍이다 |
| 4 | 방 지역 → 좌표 (API-1) | 박재현 | 아래 API 가 다 좌표를 쓴다 |
| 5 | 신고 숙소 표시 (API-6), 조건 자동 채움 (API-3) | 김현수 | 다른 앱에 없는 근거다 |
| 6 | 운전 정원·회비 근거 (API-2, API-8) | 문지훈 | 역할 추천 근거를 설문 밖으로 넓힌다 |
| 7 | 날씨, 마트, 반려동물, 홈 화면에 추가 | 나눠서 | 있으면 좋은 것 |

요구사항 번호(REQ-18~)는 팀이 고른 뒤 [주제와 요구사항](01-주제와-요구사항.md)에 붙인다.
