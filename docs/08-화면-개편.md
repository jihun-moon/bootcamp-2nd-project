# 8. 화면 개편: 무엇을 왜 바꿨나

2026-11-20. 사용자가 처음 링크를 받아 여행을 다 정할 때까지를 휴대폰(카톡 안 브라우저)으로 따라가며 막히는 곳을 고쳤다.
스택은 그대로다(Thymeleaf + jQuery + `style.css` 하나). 라이브러리·웹폰트는 더하지 않았다.

## 1. 참고한 페이지

브라우저로 열어 스크롤하며 화면을 찍고, 제목(h1~h3)과 버튼 문구를 뽑아 짜임을 봤다.

| 서비스 | 첫 화면 짜임 | 가져온 것 |
|---|---|---|
| [Wanderlog](https://wanderlog.com) | 한 줄 약속 → 버튼 둘 → 바로 아래 실제 제품 화면 → 후기 → 기능을 글·화면 번갈아 → 버튼 반복 | 제목 바로 아래 **실제 화면**, 끝에 **버튼 다시** |
| [Splitwise](https://www.splitwise.com) | "Less stress when sharing expenses **on trips.**"(끝 단어만 색) → 버튼 하나 → "Free for iPhone, Android, web" | **감정 한 줄 제목**, 강조는 한 단어만, 버튼 아래 **신뢰 한 줄** |
| [Partiful](https://partiful.com) | "ONE LINK. EVERYONE'S IN." → 세 단계(만들기 → 링크 보내기 → 같이 보기) → "No app needed", "Takes 30 seconds" | 우리와 같은 **링크 한 장으로 모으기** 전략, **30초·앱 설치 없음** |
| [토스](https://toss.im) | 화면 한 장에 짧은 한 문장("몇 번만 누르면 끝나는 송금") | **한 구획 한 메시지**. 기능 설명을 한 문장으로 줄였다 |
| triple.guide | 지금은 야놀자 NOL 할인·예약 페이지로 넘어간다 | 커머스 화면이라 참고하지 않았다 |

후기·언론 소개 칸은 넣지 않았다. 우리는 아직 사용자가 없어서 넣으면 지어낸 것이 된다.

## 2. 첫 화면(SCR-01)

전에는 제목 한 줄과 버튼 둘뿐이라 "이걸 왜 쓰지?"에 답이 없었다. 위에서 아래로 이 순서로 답하게 했다.

| 차례 | 칸 | 답하는 질문 | 까닭 |
|---|---|---|---|
| 0 | 내 여행방(로그인했을 때만) | 내 방이 어디 있지? | 다시 온 사람이 소개를 지나 방을 찾지 않게. `GET /api/me/trips`. 방 머리처럼 지역 사진 + D-day 알약 카드, 할 일 있는 방이 앞, 셋 넘으면 "더 보기". 보이는 동안 아래 붙는 시작 단추는 숨는다(2026-11-21: PC 히어로 배경 사진이 위로 넘쳐 이 박스를 덮어 글이 바랬다) |
| 1 | 제목 "단체 여행, 눈치 싸움 없이 정해요." + 버튼 + "30초 · 앱 설치 없음 · 카톡 링크" | 뭘 해 주는데? 얼마나 걸려? | Splitwise·Partiful. 3초 안에 읽히는 한 줄 |
| 2 | 역할 보드·숙소 취향 미리보기 | 실제로 어떻게 생겼어? | Wanderlog. 그림 파일 대신 실제 화면과 같은 칸(`card`, `bar`)으로 그려 글자가 또렷하고 다크 모드를 따라간다 |
| 3 | 단톡방 말풍선 | 이게 내 문제야? | 카톡 투표로 정할 때 생기는 일 세 가지. 노란 말풍선은 카톡을 떠올리게 |
| 4 | 세 단계 "링크 하나면, 모두 들어와요" | 친구들도 해야 해? | Partiful. 방장 한 명만 알면 된다 |
| 5 | 기능 6개(한 문장씩) | 다른 것과 뭐가 달라? | 토스. 근거 있는 역할, 의견 갈림, 1인 교통비, 실시간, 배려, 설치 없음 |
| 6 | 비교표(카톡 투표 · 일정·정산 앱 · TripMate) | 그냥 카톡 투표 쓰면 안 돼? | 조사 문서(07)의 차이를 한눈에. 우리가 못 하는 정산은 "쓴 돈 정산"으로 그대로 적었다 |
| 7 | 자주 묻는 것 | 돈 들어? 가입해? 내 정보는? | 망설이는 까닭을 미리 답한다 |
| 8 | 마지막 버튼 + 출처 | 이제 해 볼까 | Wanderlog. 끝까지 읽은 사람에게 다시 버튼 |

휴대폰에서는 화면 아래에 "무료로 여행방 만들기"를 붙여 둔다(`sticky-cta`). 스크롤 어디서든 엄지 아래에 버튼이 있다. 같은 버튼이 머리에도 있으면 두 번 보여서 휴대폰에서는 머리 버튼을 숨긴다.

|---|---|---|

| 방 개요(SCR-05) | 진행 막대와 참여자만 있어 무엇을 할지 몰랐다 | **내 상태에 맞는 다음 할 일 하나**: 혼자면 초대 → 내 설문 → (방장) 안 한 사람 재촉 글 복사 → 결과 보기. 초대 링크는 칸에 보여 주고 복사 버튼 |

| 역할 보드(SCR-07) | 휴대폰에서 끌기가 안 됐다(PR #5에서 고침) | 방장만 "역할 더하기"·"고치기"(REQ-12). 버튼 줄이 좁은 화면에서 넘치지 않게 줄바꿈 |
| 숙소(SCR-08) | 760px 넓이 표라 휴대폰에서 옆으로 밀어야 했다 | 숙소마다 카드. 그룹 취향 점수 순으로 "1위 · 3.0점", 있는 조건은 초록 칩, **누군가 꼭 원하는(최솟값 4 이상) 조건이 없으면 주황 칩**("온수풀 없음") |

## 4. 디자인 규칙(`style.css`)

- 색·간격·모서리는 맨 위 변수(`--accent`, `--radius` 등)에서만 정한다. 다크 모드는 변수만 바꾼다
- 휴대폰이 기본이고 넓은 화면은 `@media (min-width: 720px)`로 넓힌다. 카톡 안 브라우저로 들어오는 사람이 대부분이라서
- 누르는 것은 높이 44px 이상(`--tap`). 설문 단추·숙소 조건 칩도 같다
- 한국어가 단어 중간에서 끊기지 않게 `word-break: keep-all`
- 강조색(청록)은 한 화면에 한두 곳만. 주황(`--warn`)은 "의견 갈림·빠진 조건"처럼 사람이 봐야 할 것에만

## 5. 줄인 것

- 복사 코드가 `roles.js`·`trip.js` 두 곳에 따로 있었다 → `common.js` 의 `copyText` 하나
- 숙소 표 전용 CSS(`.thumb`)와 표를 그리던 코드 → 카드로 바뀌며 지웠다
- 부르는 곳 없는 getter 2개(보안 점검 PR)

## 6. 기본값처럼 보이는 꼴(AI 티) 덜어 내기

시루·크로노 화면 작업에서 모은 금지 목록(chrono-ui-polish 0-5절, siru-ui-polish system.md 쓰레드 근거 표)을 이 화면에 대 보고 걸린 것을 고쳤다.
결론은 "AI 가 만들어서가 아니라 아무도 생김새를 정하지 않아 기본값이 나온 것"이다. 둘 이상 겹치면 티가 난다.

| 걸린 것 | 바꾼 것 |
|---|---|
| 이모지 얹은 같은 크기 기능 카드 여섯 | 제목 + 한 줄의 목록, 위 구분선만. 넓은 화면 두 줄 |
| 모든 칩이 알약(둥글기 99) | 둥글기는 판 12, 누르는 것 6 두 단계만 |
| 모든 상자에 그림자 | 테두리만. 그림자는 떠 있는 창(시트) 하나 |
| 파스텔 상자(다음 할 일, 마지막 권유) | 보통 상자, 마지막 권유는 상자 없이 가운데 |
| 강조색이 칩·링크·체크·눈썹 글자·제목까지 | 강조색은 주 단추와 고른 탭만. 링크는 글자색 + 밑줄 |
| 카드 안 카드(미리보기, 참여자) | 줄과 구분선(`.rows`), 참여자는 상자 없는 줄 |
| 출처 없는 숫자(미리보기 8,800원) | "예시 화면 · 가평 2박 3일, 8명" 캡션. 값은 그때 개발용 예시 방에서 실제로 나온 것(개발용 예시 방은 2026-11-20 에 지웠고, 지금 예시 방은 시험용 `TestTripData` 와 `/demo` 체험 방이다) |
| 반투명 유리 머리·아래 띠 | 바탕색 그대로 + 아래·위 선 |
| 10·14·18·22px 같은 간격 | 4 배수(4·8·12·16·24·32·48) |
| 글 속 이모지(😅🎉🙏), 굵기 800 | 이모지 0, 굵기는 제목 600·본문 400 |

## 7. 쓰레드 조사와 두 번째 덜어 내기(2026-11-20)

쓰레드에서 "랜딩페이지 디자인", "AI 티 디자인", "랜딩페이지 전환율"로 찾아 읽었다(좋아요·팔로우 없이 읽기만).
쓸 만한 것은 @theburrow_hq 글이 소개한 Impeccable 의 [AI 티 점검 목록](https://impeccable.style/slop)이었다. 70여 줄을 이 화면에 대 보고 걸린 것을 고쳤다.

| 걸린 줄 | 바꾼 것 |
|---|---|
| kicker-above-heading(제목 위 작은 글자) | "7~8명 단체 여행 준비"를 없애고 설명 문장 첫머리로 |
| cream-palette(크림·베이지 바탕) | `#f7f6f2` → 중립 회백 `#f6f7f8`, 선·보조 바탕도 회색 계열로 |
| identical-card-grids(같은 무게 카드 줄) | 핵심 둘(역할 추천·의견 갈림)은 설명 + 실제 화면 조각으로 크게, 나머지 넷은 한 줄 목록 |
| unbalanced-heading, straggler(마지막 줄 한 단어) | 제목 `text-wrap: balance`, 본문 `text-wrap: pretty` |
| line-length | 본문 한 줄 68자(`max-width: 68ch`) |
| tiny-text | 보조 글자 13~14px 로 |

그대로 둔 것: 세 단계 번호(순서가 의미 있다), 비교표(표가 맞는 자리), 시스템 글꼴(팀 스택에 웹폰트가 없다).

## 8. 움직임: 실시간으로 본 것과 정한 값

스크린샷으로는 움직임이 안 보여서 페이지를 띄워 놓고 몇 초 간격으로 찍고, `document.getAnimations()` 로 걸린 애니메이션의 길이·이징을 읽었다.

| 본 곳 | 움직임 | 우리 적용 |
|---|---|---|
| Partiful 첫 화면 | 사진 위 단톡방 메시지가 "…"(입력 중) 뒤에 하나씩, 중간에 **실제 초대 카드**가 들어온다(약 10초 한 바퀴). 메뉴는 280ms `cubic-bezier(0.2,0,0,1)` | 첫 화면 휴대폰: 메신저 방 → 초대 링크 카드 → TripMate 역할 보드로 넘어가 줄이 하나씩, 교통비 숫자가 올라감 |
| Partiful 세 단계 | 단계마다 실제 앱 화면을 담은 휴대폰 | 세 단계 미니 휴대폰을 실제 화면 부품으로 |
| 토스 | 절 4곳을 `position: sticky` 로 붙여 두고 스크롤하면 사람 손의 휴대폰으로 다가가 앱 화면이 된다. 화면 안 요소는 140~300ms | PC 에서 세 단계를 한 단계 한 화면으로: 휴대폰이 왼쪽에 붙어 있고 다음 단계가 올라와 밀어낸다 |
| Emil Kowalski "Great Animations"(쓰레드 디자인 스킬 글에서 찾음) | 빠르게(300ms 안, ease-out), 목적 있는 곳만, transform·opacity 만, 중간에 되돌릴 수 있게 | 아래 토큰 |

정한 값(`style.css` 맨 위): `--ease: cubic-bezier(0.2,0,0,1)`, `--dur-fast 120ms`(누름·hover), `--dur 200ms`(카드 들림), `--dur-slow 400ms`(장면).

| 어디 | 움직임 | 까닭 |
|---|---|---|
| 단추·설문 단추·카드 누를 때 | `scale(0.97)` 120ms | 실제 단추처럼 눌린 느낌. 휴대폰에서도 보이게 hover 와 따로 |
| 마우스 올릴 때(마우스 있는 기기만) | 단추 바탕·테두리, 카드 2px 들림, 링크 밑줄 진해짐 | 휴대폰은 hover 가 남아 "눌린 채"로 보여서 `@media (hover: hover)` 안에만 |
| 첫 화면 휴대폰 | 마우스 쪽으로 최대 4도 기울기(프레임당 한 번) | 손에 반응한다는 느낌만, 읽기를 방해하지 않게 작게 |
| 절 나타남 | 16px 올라오며 0.5s, 한 번만 | 내용은 기본으로 보이고 JS 가 있을 때만 움직인다(움직임이 실패해도 읽힌다) |
| 움직임 줄이기 설정 | 모든 움직임 끔, 휴대폰은 결과 화면만 | 어지럼을 느끼는 사람 |
| 화면 밖 | 휴대폰 재생을 멈춘다 | 보지도 않는데 계속 돌지 않게 |

색 토큰도 다시 셌다: 노랑(`--sun`)은 안내 칸 한 곳에만 써서 주황과 합쳤다. 색은 청록(주 동작)·주황(봐야 할 것)·빨강(오류)·카카오 노랑(카카오 단추) 넷이다.
