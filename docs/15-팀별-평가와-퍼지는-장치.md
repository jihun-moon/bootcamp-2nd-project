# 15. 전문팀별 평가와 SNS 에서 빨리 퍼지게 하는 장치

2026-11-20. 지금 TripMate(PR #10 기준)를 각 팀 입장에서 차갑게 본 것과, 퍼지는 구조를 어떻게 만들지 정리했다. 근거는 docs/11·12·13·14 조사.

## 1. 팀별 평가

### 제품(PM)
- 잘 된 것: 단체 여행에서 제일 오래 걸리는 "정하기"(날짜·역할·숙소·돈·장보기)를 한 방에 모았다. 예약 앱·정산 앱이 비워 둔 자리다(docs/12).
- 아쉬운 것: 여행 "중"과 "후"가 약하다. 영수증까지는 있지만 다녀온 뒤 남은 돈, 다음 여행으로 이어 가기가 없다(docs/14 아이디어 10). (2026-11-20 기준, 그 뒤 2탄 방·정산을 넣었다)
- 다음: 같은 멤버로 다음 여행(규칙 복사, 지난번 운전·총무는 점수에서 빼 줌)이 재방문을 만든다.

### 디자인
- 잘 된 것: 색 하나(청록)와 회색 단계, 1px 테두리, 4·8 배수 여백, 휴대폰 360px 에서 11개 화면 삐져나감 0.
- 아쉬운 것: 방 화면들은 아직 "상자 + 글"이 많다. 사진은 개요 띠 하나뿐. 숙소 카드 외에는 그림이 없다.
- 다음: 빈 화면(숙소 0곳, 장보기 0줄 맡음)에 일러스트나 사진 한 장과 할 일 하나만.

### 홍보·마케팅
- 잘 된 것: "운전 누가 해?" 한 줄 공감, 공감 숫자(76·74·82%), 우리 자리 세 줄, 영수증 칸.
- 아쉬운 것: 실제 사용자 숫자와 후기가 0. 퍼질 그림이 영수증 하나뿐이고 역할 테스트 결과는 글로만 나간다.
- 다음: 역할 테스트 결과를 그림 카드로(인스타 스토리 9:16), 영수증·카드 그림 바닥에 주소를 박아 "그림이 곧 광고"가 되게.

### MZ 사용자
- 꽂히는 것: "엑셀부터 켜는 총무형", "단톡방 싸움 0회", 영수증이 프린터에서 뽑히는 것, 확정 도장.
- 밋밋한 것: 결과를 나눌 때 글이 길다. 그림 한 장, 한 줄이면 된다.

### 개발·보안
- 잘 된 것: 새 라이브러리 0, 권한 확인(본인·방장), 입력 범위, CSP, 시험 103개(3·8·15명 시나리오 포함, 2026-11-20 기준. 지금 수는 README 테스트 절), N+1 묶어 읽기.
- 아쉬운 것: 메모리 DB 라 서버를 다시 켜면 방이 사라진다(배포 때 Postgres). 카톡 공유는 지금 글 복사/공유 창이고 카카오 피드 카드는 아직.

## 2. 퍼지는 구조(바이럴 고리)

```
방장이 방을 만든다 → 초대 글(규칙·되는 날 부탁 포함)이 단톡방에 → 친구 7명이 링크로 들어옴(설치 없음)
→ 설문 중 역할 테스트 결과 그림을 자기 스토리에 → 그걸 본 다른 무리가 "우리도" → 새 방
→ 여행 끝 영수증 그림이 단톡방·스토리에 → 그림 바닥 주소로 새 방
```

한 방이 8명을 데려오고, 그 8명 각자가 다른 무리를 갖고 있다. 퍼질 그림 두 장(역할 카드, 영수증)이 고리의 축이다.
