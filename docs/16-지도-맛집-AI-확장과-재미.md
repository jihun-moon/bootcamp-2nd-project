# 16. 지도·맛집·숙소 검색·AI 로 넓히기, 그리고 다시 오게 하는 재미

2026-11-20. 지훈이 물은 네 가지를 조사로 답했다.

1. 숙소를 우리 화면 안에서 바로 찾으면 되지 않나
2. 옆에 지도를 띄우고 SNS 맛집·리뷰까지 보이면 되지 않나
3. 냉정하게 보면 이 플랫폼에 끌리나
4. 재미가 있어야 다시 쓰지 않나

조사는 세 갈래로 했다.

- 한국 비슷한 서비스: 웹 검색, 출처는 끝에
- 지도·장소 API 약관: 공식 문서, 카카오 데브톡 스태프 답
- 스레드: 직접 검색하고 영상은 프레임으로 끊어 봤다

## 1. 시장이 바뀐 것(2026 하반기)

트리플은 2026-11-03에 앱과 웹을 닫고 NOL 로 합쳤다. 스레드에 "트리플 11월 종료, 정착한 앱 추천해 줘" 글이 올라왔다(2026-09-19). 댓글에는 작은 서비스들이 직접 홍보하러 왔다.

| 서비스 | 하는 일 | 우리와 겹침 |
|---|---|---|
| 트립아지트 | 웹, 장소를 담으면 지도에 동선·이동시간, 링크로 같이 고침, 트리플 가져오기, 지출 관리 | 가장 가깝다. 투표·역할·1인 얼마·취향 거르기는 확인 못 함 |
| 투래블 | 트리플 링크 가져오기 | 일정 |
| 맵온 | 사진 위치로 다녀온 곳 칠하기 | 없음(여행 뒤 기록) |
| novas(스레드 개발 일지) | AI 입력칸 + 장소 카드 가로 넘김 + 별점 | 없음(혼자 쓰는 기록) |

AI 장소 추천은 대형사가 이미 다 갖췄다.

- 네이버지도: 플레이스 AI 브리핑, 플레이스 에이전트(2026-09)
- 카카오: AI메이트 로컬, 카나나 인 카카오톡(대화 맥락으로 장소 제안, 카톡 예약)
- 트립닷컴: TripGenie

모두 **혼자 쓰는 대화형**이다. 단톡방 단위로 쓰는 기능이나 여러 사람의 조건을 합치는 기능은 보도에 없다.

같이 고르는 기능은 이미 있다.

- 캐치테이블 "함께 고르기": 식당 후보를 링크로 투표한다. 하루 생성 수가 6개월 새 20배로 늘었다.
- 카톡 게시판 다중투표(2026-07): 날짜·장소·시간을 한 번에 투표한다.

"같이 고르기"는 수요가 큰 대신 투표만으로는 차별이 안 된다는 뜻이다.

## 2. 냉정한 판단

**지도 + 맛집 목록 + 리뷰만 붙이면 진다.**

- 네이버·카카오 지도 앱이 장소 데이터, 리뷰, AI, 예약까지 다 갖고 있다.
- 트립아지트가 이미 같은 꼴(웹, 링크, 지도 동선)을 무료로 한다.
- 우리 지도가 이들보다 나을 수 있는 건 하나다. **우리 방 사람들 정보로 거른다**는 것.

**SNS 리뷰를 우리 화면에 모아 보이는 것은 약관이 막는다.**

- 네이버 검색 API: 결과를 가공 없이 따로 보여야 한다. 캐시를 포함한 저장, 지역정보 DB화, AI 입력이 금지다.
- 인스타 해시태그 검색: 앱 심사(Public Content Access)가 필요하고, 7일에 해시태그 30개까지다.
- 스레드 키워드 검색: 권한 심사가 필요하다.
- 그래서 리뷰는 "링크 목록 그대로"까지만 된다. 대신 방 사람이 직접 붙인 릴스·블로그 링크는 우리 것이라 모아서 투표에 쓸 수 있다.

**숙소를 우리 안에서 찾는 것은 반만 된다.**

- 되는 것: 숙소 목록과 위치. 카카오 로컬 숙박(AD5), TourAPI 숙박(32), 고캠핑.
- 안 되는 것: 실시간 가격과 빈방.
  - 야놀자·여기어때·네이버 호텔은 공개 API 를 확인 못 했다.
  - 아고다는 승인받은 파트너만 가격 API 를 받는다.
  - 에어비앤비는 초대받은 곳만 된다.
- 그래서 지금처럼 숙소 주소를 붙이면 가격을 읽는 길은 남긴다. 그 앞에 "지도에서 근처 숙소 고르기 → 예약 사이트 열기 → 주소 붙이기"를 한 흐름으로 잇는다.

**끌리나(내가 8명 MT 총무라면).**

- 날짜 맞추기, 역할, 1인 얼마, 장보기, 영수증은 쓴다. 단톡방에서 하던 일을 덜어 준다.
- 약점: 여행은 1년에 몇 번이다. 한 번 쓰고 다음 여행까지 열 일이 없다. 다시 오게 할 고리가 없다.

## 3. 우리만 할 수 있는 지도(아이디어)

| 아이디어 | 기존에 있나 | 판정 |
|---|---|---|
| A. 방 지도: 설문(못 먹는 것, 술, 예산, 이동 불편)을 합쳐 거른 맛집·카페만 표시 | 네이버·카카오 AI 는 한 사람 조건만 본다 | 진짜 차별 |
| B. 숙소 반경 마트·편의점 → 장보기 목록과 잇기("숙소 2km 안 마트 없음, 오는 길 하나로마트에서 사세요") | 확인 못 함 | 진짜 차별 |
| C. 지도 위 투표 + 마감 + 1인 얼마·방 규칙 연결 | 투표만은 캐치테이블·카톡·구글에 있다 | 연결이 차별 |
| D. 역할을 반영한 하루 동선(운전자 금주 시간, 장보기 담당 마트 들르기, 체크인 시각) | 트립닷컴·카나나는 개인 일정만 | 진짜 차별 |
| E. 방 사람이 붙인 릴스·블로그 링크가 후보함으로 모여 투표 | Pin-It·쏙핀은 개인용 | 부분 차별, AI 요약은 하지 않는다 |
| F. 15명 들어가는 식당 | 수용 인원 데이터가 API 에 없다 | 멤버가 "전화해 봄" 체크로 보완 |

**쓸 조합(무료, 약관 확인함).**

- 카카오맵 JS SDK: 하루 30만 건. 로그인에 쓰는 앱 하나에 몰아야 한다.
- 카카오 로컬: 하루 10만 건, 실시간 검색만. 장소 ID 와 place_url 만 저장할 수 있다.
- TourAPI 국문·고캠핑: 저장할 수 있고 AI 근거로도 쓸 수 있다. "출처: 한국관광공사"를 표기해야 한다.
- AI 입력: TourAPI, 우리 DB, 사용자가 쓴 것만 넣는다. 네이버 검색 결과와 카카오 응답은 넣지 않는다.
- 카카오 데브톡 151916 에 같은 꼴 팀 프로젝트 질문이 있었다. 스태프 답(2026-10-01): 장소 ID 저장, 공공데이터 좌표로 마커, place_url 로 카카오맵에 넘기기는 허용이다.

**팀 규칙과 겹치는 곳.**

- 카카오맵 SDK 는 스택 표에 없는 새 기술이다. 넣기 전에 팀이 정해야 한다.
- 숙소 근처 지도는 숙소 기능(김현수 담당)과 맞닿는다. 그쪽 파일은 말로 먼저 맞춘다.

## 4. 다시 오게 하는 재미

스레드와 커뮤니티에서 반응이 컸던 것은 "결과를 남에게 보이는 것"과 "우리끼리 기록"이었다.

| 장치 | 왜 다시 오나 |
|---|---|
| 우리 모임 방: 여행이 끝나도 방이 남고 "같은 멤버로 다음 여행" 한 번 누르기. 규칙·사람 그대로 | 다음 여행 때 새로 만들 이유가 없다 |
| 역할 기록: "재현 운전 3번째" → 다음 추천에서 운전 점수 빼 줌. 지난 총무는 쉬게 | 기록이 쌓일수록 공정해진다 |
| 역할 카드 그림(9:16): "엑셀부터 켜는 총무형" 결과를 스토리용 그림으로 | 스토리에 올라가면 다른 무리가 들어온다 |
| 체크아웃 당번 뽑기: 마지막 날 설거지·분리수거를 돌림판으로(돈 걸지 않음) | 여행 중에 한 번 더 연다 |
| 여행 D-day 와 준비 체크 알림: "D-3, 장보기 3줄 아직 아무도 안 맡음" | 여행 전 사흘 동안 연다 |
| 영수증 뒤에 "우리 방 한 줄 후기"와 사진 한 장, 1년 뒤 "작년 오늘 가평" | 다녀온 뒤에도 연다 |

## 5. 사용 영상과 스크롤(스레드)

- "SNS 에서는 멈춘 캡처보다 10초짜리 원테이크 영상이 체류시간과 노출에 유리하다"는 글이 반복해서 나왔다.
  - 도구: onetake(Remotion 바탕, 비상업 무료), OpenMotion.
  - 꼴: "입력칸이 앱 화면으로 펼쳐지고, 앱이 폰으로 바뀌고, 선 하나가 다음 장면으로 이어진다."
- "AI 가 만든 랜딩이 다 비슷한 이유" 글(MotionSites, 별 1,600개)은 세 가지를 짚었다.
  - 막연한 기획, 진짜 사진·영상이 없음, 결과를 아무도 안 봄.
  - 고치는 법: 글자 크기, 간격, 움직임 타이밍을 숫자로 정하고, 스크린샷으로 모바일 넘침을 검사한다.
  - 우리는 실제 사진, 360·390·834·1440px 넘침 검사, 움직임 시간(120·200·400ms)을 이미 숫자로 둔다.
- 움직임 참고 사이트: 60fps.design(버튼, 스크롤, 화면 전환).
- 우리 첫 화면은 이미 휴대폰 안 원테이크(단톡방 → 초대 → 역할 보드)를 돌린다. 모자란 건 **SNS 에 올릴 영상 파일**이었다.
  - 첫 화면을 휴대폰 크기(1080x1920, 9:16)로 찍은 24초 영상을 만들었다. 크롬을 화면 없이 띄워 CDP 화면 중계 프레임을 모으고, 같은 크롬의 MediaRecorder 로 mp4 를 만들었다.
  - ffmpeg 는 이 PC 보안 정책이 실행을 막아 쓰지 않았다.
  - 파일은 `build/promo/` 에 있다. 저장소에는 올리지 않는다(13MB).
