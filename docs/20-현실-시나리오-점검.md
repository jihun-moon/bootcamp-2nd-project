# 20. 현실 시나리오 점검 (2026-11-21)

지훈이 물었다. "각자 다른 지역에 살고 차 2대로 가는데, 차마다 가까운 곳에서 모여 가는 경우까지 다 생각했나. 손일은 적고 복잡하지 않나."
8명 예시 방을 처음부터 끝까지 돌리며(소개 화면을 찍은 `build/promo/tour.mjs`, 차 두 대 장면 `seed-cars.mjs`) 실제로 일어날 일을 하나씩 대 봤다.

## 이미 되던 것(다시 확인)

- 둘이 당일치기, 15명 4박, 차 없음, 아무도 술 안 마심(`FlexibilityTest`)
- 늦게 온 사람도 역할, 손으로 옮긴 카드는 그대로(`SevenFriendsStoryTest`)
- 방 나가기·빼기: 먼저 낸 돈은 정산에 남는다. 방장이 나가면 다음 사람이 방장(`LeaveTripTest`)
- 같은 이름 손님은 "민재(2)", 카톡 안 브라우저처럼 로그인이 끊긴 곳은 손님 기억하기와 정산 받는 링크
- 회비가 남으면 총무가 돌려주고 모자라면 더 보낸다. 총무가 나가도 낸 돈은 남는다(`DuesTest`)
- 두 사람이 동시에 누름: 역할 카드 409, 2탄 방 하나, 정산 링크 409 뒤 다시
- 방 지우기는 모든 기능 표를 지우고 다른 사람 화면은 첫 화면으로(`DeleteTripTest`)

## 손일 세기(참여자 한 사람 기준)

| 할 일 | 누르는 수 |
|---|---|
| 초대 링크 → 이름 → 들어오기 | 2 |
| 되는 날 | 날짜 수만큼(보통 3~5) |
| 설문 | 5 |
| 숙소 표 | 1 |
| 장보기 "내가 살게" | 맡을 때만 1 |
| 차 | 0(다른 차나 따로 갈 때만 1) |
| 회비 "냈어요" | 1 |
| 정산 "보냈어요" | 1 |

방장은 여기에 날짜 정하기 1, 규칙 3, 모이는 곳, 회비 금액이 더해진다. 차마다 태우는 곳은 그 차 운전자가 적어서 방장 혼자 다 챙기지 않는다.

## 소개 페이지를 홍보·마케팅 눈으로(2026-11-21)

스레드에서 다시 본 것: 스크롤에 붙어 자연스럽게 넘어가는 랜딩(ScrollTrigger·부드러운 스크롤), 셰이더 화면 효과(shaders.com), 랜딩 17단계 구조와 전환율 피드백, 그리고 네이버 1페이지 병원 사이트 50곳을 뜯어보니 키워드보다 "실제로 운영하는 곳 티"가 더 중요했다는 글.

| 본 것 | 고친 것 |
|---|---|
| 첫 화면 휴대폰이 말풍선 하나에 비어 보였다 | 운전·숙소·날짜 고민 셋을 바로 띄운다 |
| "이렇게 굴러가요"가 손으로 그린 작은 휴대폰 셋 | 실제 앱 화면 열 장, PC 는 스크롤하면 고정 휴대폰 화면이 바뀌고 누르는 곳에 동그라미 |
| 목업이 단순한 테두리 | 카메라 구멍·상태줄·옆 단추, 노트북 카메라·받침 |
| 끝 절이 가운데 한 줄이라 PC 양옆이 빔 | 왼쪽 말·시작 단추, 오른쪽 노트북+휴대폰(웹앱), 뒤 사진이 천천히 다가옴 |
| 끝 절 휴대폰 안 글씨가 깨알 | 1.35배로 다시 찍고 휴대폰을 크게 |
| 스크롤이 뚝뚝 넘어감 | 라이브러리 없이 scroll-driven: 첫 화면이 빠지며 흐려지고, 휴대폰은 느리게, 사진 띠는 안에서 움직이고, 맨 위에 읽은 만큼 차는 막대 |
| 기능 칸(숙소·교통비·장보기·콕)이 열 장과 같은 말을 또 함 | 열 장에 없는 둘(말하기 어려운 사정, 술값 0원)만 남김 |
| "PC 에서도 돼요?"가 없다 | 자주 묻는 것에 한 줄, 끝 절 웹앱 네 줄, manifest 로 홈 화면에 추가 |
| 실제로 운영하는 곳인지 티가 없다 | 바닥에 팀 프로젝트 표시와 개인정보 한 줄(계좌·전화번호 안 받음, 정산 링크는 이름·금액만) |

아직 약한 것: 실제 사람이 쓴 흔적(후기·실제 방 수·실제 영수증)이 0이다. 지어낼 수 없어서 배포 뒤 첫 방들의 영수증을 허락받아 올리는 것이 다음 할 일이다. 사람들이 실제로 쓰는 장면 영상(AI 영상 포함)은 여기서 만들 수 없어, 히어로 뒤 사진 자리를 영상으로 바꿀 수 있게만 해 뒀다.
