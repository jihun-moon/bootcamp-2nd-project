# 역할 배정 알고리즘

`POST /api/trips/{id}/roles/recommend` 가 설문으로 역할을 처음부터 다시 짠다.
코드: `backend/src/main/java/com/tripmate/role/` 의 `RoleScorer`, `HungarianAssigner`, `RoleController.recommend`.

## 1. 점수표 만들기

사람 × 역할마다 설문 답으로 점수와 근거를 낸다(`RoleScorer`). 근거는 보드 카드에 그대로 보인다.

| 역할 | 더하는 것 | 빼는 것 |
|---|---|---|
| 총무·타임라인 | 계획형 +3, 큰 틀 계획 +1 | 돈 관리 싫음 -5 |
| 운전 | 차 있음 +4 | 따로 출발 -2, 이동 제약 -3, 운전 싫음 -5, **차 없음·설문 전은 금지** |
| 장보기 | 차 있음 +1, 밖 활동 선호 +1 | 이동 제약 -3 |
| 바베큐 세팅 | 숙소 휴식 선호 +2, 이동 제약 +2 | 요리 싫음 -5 |
| 여행 DJ | 숙소 휴식 선호 +1, 이동 제약 +2 | |
| 기록 담당 | 밖 활동 선호 +2 | |

이동 제약은 다른 사람에게도 보이는 근거라 "이동 적은 역할 우선"이라는 말로만 쓴다.

## 2. 칸 펼치기

운전(2명), 바베큐(2명)처럼 capacity 가 2 이상인 역할은 칸을 그만큼 늘린다.
필수 역할의 **첫 칸**에만 +100 을 얹어서 사람이 모자라도 필수 역할이 먼저 찬다.

## 3. 헝가리안으로 합이 가장 큰 배정 찾기

각자에게 1등 역할을 주는 욕심 방식은 두 사람이 같은 역할을 원할 때 전체 합이 나빠진다.

```
        총무  운전
A        10    9
B        10    1
욕심:   A→총무, B→운전   합 11
최적:   A→운전, B→총무   합 19
```

점수표를 정사각형(사람 + 칸)으로 펼쳐 O(n³) 헝가리안으로 푼다.

- 사람마다 "미배정" 열(-500): 보통 감점보다 훨씬 나빠 웬만하면 누구나 역할을 받지만, 금지 칸(-1000)보다 나아서 차 없는 사람이 운전에 억지로 들어가지 않는다
- 칸마다 "빈 사람" 행(0): 사람이 모자라면 선택 역할 칸은 비어 있을 수 있다

## 4. 저장

이전 배정을 모두 지우고(손으로 옮긴 것 포함) 새로 넣는다. 사람마다 근거 목록이 같이 저장된다.
